# System Architecture: Resume Analyzer

Based on the core objectives outlined in the problem statement, the following is a simple, high-level architecture designed to parse resumes and leverage the Groq LLM API to evaluate candidate eligibility.

## 1. High-Level Architecture Overview

The system follows a standard three-tier architecture:
1. **Frontend (User Interface):** For user interaction (uploading documents, viewing the LLM's evaluation).
2. **Backend (API & Orchestration):** To handle requests, extract text from documents, and orchestrate calls to the Groq API.
3. **LLM Engine (Groq API):** The core intelligence responsible for analyzing the resume text and determining eligibility.

---

## 2. Component Breakdown

### A. User Interface (Frontend)
*   **Purpose:** Provides a simple dashboard for HR recruiters.
*   **Key Features:**
    *   Upload portal for resumes (PDF, DOCX formats) and Job Descriptions (JD).
    *   Results view to display the candidate's eligibility assessment, strengths, and weaknesses as generated by the LLM.

### B. Backend API / Application Layer
*   **Purpose:** Acts as the bridge between the UI and the Groq API.
*   **Key Features:**
    *   File upload handling and temporary storage.
    *   Prompt construction logic (combining extracted resume text with the job description into a structured prompt).
    *   API integration with Groq to send the prompt and receive the analysis.
    *   Database interactions (optional, for storing analysis history).

### C. Document Parsing Module
*   **Purpose:** Extracts machine-readable text from uploaded documents.
*   **Key Features:**
    *   Uses libraries (e.g., PyPDF2, pdfminer, python-docx) to extract raw text from resumes and JDs before passing them to the LLM.

### D. LLM Engine (Groq API)
*   **Purpose:** Provides the cognitive analysis of the candidate.
*   **Key Features:**
    *   Processes the structured prompt provided by the backend.
    *   Analyzes the resume text against the JD.
    *   Returns a detailed eligibility report, matching scores, and reasoning.

---

## 3. Data Flow (How it works)

1.  **Input:** Recruiter uploads a Job Description and a Candidate's Resume via the Frontend.
2.  **Extraction:** The Backend sends the files to the Parsing Module, which extracts the raw text.
3.  **Prompt Engineering:** The Backend constructs a specific prompt containing the JD, the extracted Resume text, and instructions on how to evaluate the candidate.
4.  **LLM Analysis:** The Backend sends this prompt to the **Groq API**.
5.  **Response Handling:** The Groq API returns the eligibility analysis, which the Backend formats if necessary.
6.  **Output:** The Backend sends the final evaluation report to the Frontend for the recruiter to review.
